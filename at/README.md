# at — AT 响应解析工具 + 接收搬运

> ⚠️ **本模块不再是 AT 引擎。** 命令的组帧、命令-响应配对、URC 分发**全部**
> 归 `lmqtt/`（经 `at_port_t.cmd_exec_raw` 注入）。这里只剩两件事：
> 响应行缓冲的解析，以及把串口字节搬给引擎。

## 来源

原为 **RT-Thread 的 AT 组件**
（`Copyright (c) 2006-2021, RT-Thread Development Team`，**Apache-2.0**），
出处是 durian 发布包内的 `alumy-none/driver/net/at/at_client.c`。

**为什么先收编它**：原先它以**预编译库成员**的形式提供，而固件的**串口字节所有权**
落在它手里 —— `client_parser` 是对 `iot_uart_recv()` 的**唯一读者**，
lmqtt 只能靠 `s_raw_cb` 搭便车，且 AT 的回执归属问题无处可修。

**为什么又把它拆掉**：收编之后才看清，"两个各自组帧的引擎共读一根串口"本身就是
缺陷的根源 —— AT 的 `OK`/`ERROR` 行**不带命令标识**，一方命令的收尾 `OK` 必然
被另一方看见，而彼时另一方必然不在窗口，"这份回执归谁"就此失去定义。
**⇒ 只留一个引擎。** 详见 `local/docs/tasklist.md` 的 C4。

## 现在的分工

| | 管什么 |
| --- | --- |
| `at/`（本目录） | **响应行缓冲的解析**（`at_resp_*` 一族）与**接收搬运任务** |
| `lmqtt/` | AT 通道的**唯一引擎**：组帧、配对、URC 分发，以及 LMQTT 指令族 |

## 与 lmqtt 同规矩

| 要点 | 说明 |
| --- | --- |
| **不依赖任何 OS/MCU** | 平台能力全部经 `at_port_t` 注入（7 个原语：内存 / 搬运任务 / AT 通道 / 时间） |
| **日志/断言走编译期** | 使用方定义 `AT_CONFIG_FILE=<自己的配置头>`，在其中给出 `AT_LOG_IMPL` / `AT_ASSERT_IMPL`；不定义则展开为空宏 |
| **不持有命令事务** | 不再自建互斥、信号量与行缓冲 —— 那些只能有一个所有者，就是 AT 通道引擎 |
| **错误码是冻结的契约** | 见 `at_types.h` |

## 状态

| 步 | 内容 | 状态 |
|---|---|---|
| **C1** | 原样收编（行为一字未改） | ✅ 判据：固件 map 里 `libdurian(...at_client.o)` 段数 = 0 |
| **C2** | 切出 `at_port_t`（5 类 14 个符号）由使用方注入 ⇒ **脱 OSAL** | ✅ 判据：独立 CMake 构建通过（PC 上零 OS 依赖）+ 固件四场景 |
| **C3** | 自研 nt26e（在本仓之外，见固件仓） | ✅ |
| **C4** | **命令通道交还 lmqtt**，本模块退化为工具 | ✅ 判据：四场景 PASS + `stray_*` 零增长（2026-10-08 上板） |

**C2 的实测代价**（历史）：`at_client.o` 3,996 → 4,572 B（**+576，+14%**），
另加移植层 198 B。原因：直接调用换成经函数指针表的间接调用，编译器无法内联。
这是"平台无关"的代价，与 lmqtt 同一形态。

**C4 的实测收益**：固件 Flash 余量 **+1,664 B** —— 删掉的解析逻辑远比新增的搬运多。
